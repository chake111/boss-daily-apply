# 踩坑全记录（26 条）

> 每条都来自实际失败与排查。按「现象 → 根因 → 处置」写，照做即可，不用重新发明一遍。
> 如果你在这些坑里又踩了一次，说明流程里少了一道校验——补在 `scripts/` 里，别只记在脑子里。

---

## 环境类

### 1. 浏览器被会话回收，扩展跟着掉

**现象**：`Start-Process` / `cmd //c start` 拉起的 Chromium 浏览器，1~2 分钟内进程消失，WebBridge 扩展断连。

**根因**：这两种方式启动的子进程挂在当前会话下，会话结束就被回收。

**处置**：用 `python scripts/browser.py --launch`。它让桌面 shell 去拉
（Windows `explorer.exe` / macOS `open -a` / Linux `xdg-open`），进程归属到桌面，
不会被回收。bash 里直接调 `explorer.exe` 会静默无反应（实测两次）。

### 2. `hidden=true` 时懒加载停住，`grew` 永远是 false

**现象**：`walk --more` 连续返回 `grew:false`，看起来"每页都到底了"，但换页明明还有卡。

**根因**：Chromium 系浏览器的原生遮挡检测——窗口被完全盖住时 `document.hidden=true`，
BOSS 的懒加载直接停住。这不是"走空"，是"没加载"。

**处置**：走 `&page=N` 分页（第 3 步）。**B 路禁止用 `grew:false` 判词走完**，
正确判据是"逐页把 fresh 投/判到 0，且连续两页为 0"。

### 3. 分页结果会重排

**现象**：同一个 `page` 两次加载，卡片不同；`fresh=0` 但下一页又有。

**根因**：BOSS 每次请求都重排/补位。

**处置**：`fresh=0` 要**同一个 page 连测两次**再判空。

### 4. `activate_tab` / 点任务栏 / `ShowWindow` 都救不回前台

**现象**：窗口最小化或被遮挡后，怎么激活都是 `hidden=true`。

**根因**：`activate_tab` 只切标签不抬窗口；`ShowWindow` 被安全策略拦编译调用；
最小化窗口 `GetWindowRect` 只有 158x26，按尺寸过滤找不到主窗口；WebBridge 没有 focus/raise 动作。

**处置**：别浪费轮次，直接走分页兜底（第 3 步）。

## 投递流程类

### 5. `deliver` 会把 URL 打回无参数状态

**现象**：投完一份，后续出来的全是社招卡，实习筛选没了。

**根因**：投递弹窗会把页面带回推荐页/搜索首页；`_present_next` 在 URL 漂走时导航回
**不带 page 也不带 jobType** 的搜索首页。

**处置**：每 `deliver` 成功一次，重跑第 3 步的导航代码块，把 `page` 和 `jobType` 设回当前值。

### 6. 批量机械过滤会把当前卡无声跳过

**现象**：跑完批量 reject 脚本，发现当前那张卡既没投也没拒，回头补判。

**根因**：脚本从"下一张"开始扫，当前卡的游标已经被它推过去了。

**处置**：**先把当前卡判完（投或拒），再跑批量脚本**。实测两次都栽在这。

### 7. 判否必须 `reject` 留痕

**现象**：同一张卡反复出现在 `walk` 里，每次都要重判。

**根因**：`rejected_jids` 没写入，去重失效。

**处置**：除了 deliver，**任何"离开这张卡"的动作前都要先 `reject`**。
否则还会让"新增判否"少算、合格率虚高。

### 8. `delivered` 记录没有时间戳

**现象**：想算今日累计，发现旧记录全都没有 `delivered_at`。

**根因**：早期版本没写这个字段。

**处置**：开工记基线（第 0 步），收尾用 `daily_log.json` 求和。别想靠"数总数"倒推。

### 9. 弹窗只点「留在此页」

**现象**：点了「继续沟通」跳进聊天页，返回后列表顺序全乱。

**根因**：「继续沟通」会导航到 `/web/geek/chat`，返回时搜索页重建、游标失效。

**处置**：投递主流程全程不打开聊天页。弹窗只点「留在此页」。

### 10. 别按 fresh 多少决定投什么

**现象**：40 份里 20 份是 AI 岗，而简历里只有 1 个项目撑 AI。

**根因**：AI 岗位在 BOSS 上供给天然多，纯按 fresh 降序排，结构会被最不缺人的方向拉走。

**处置**：按「证据强度」定配额（`config/supply_mix.json`），供给不足的方向自动封顶、
缺口回补，而不是降标准凑数。

### 11. 同名多岗位共用一个会话

**现象**：一家公司投了两个岗位，但 BOSS 里只有一个会话，口号和简历图只能发一份。

**根因**：会话按公司维度建立。

**处置**：按**最后一次投递**的 direction 取桶，只发一份。

### 12. `fresh=0` 要分两种

**现象**：某个词报 `p1:0/0` 被记成「已挖空」，下轮直接跳过。

**根因**：那次其实是页面没加载出来；复测同一词 fresh=11。

**处置**：`supply_probe.py` 首屏 0 张会自动重试一次，仍失败标 `⚠️ 加载失败`。
**看到这个标记一律当"未知"，别当"没有"**，补测一次再定。

### 13. 词表里要留一个「用不上」组

**现象**：某个方向供给全场最多，但技术栈里根本没有。

**处置**：权重设 0（永不分份数），只在表里显示「可用 X / 实投 0」——
让你看见这堆供给，但不被它带偏。

### 14. `hidden=true` 时右侧详情面板可能是空的

**现象**：`open` 返回 `panel_ok:false`，`.job-detail-box` 文本长度为 0。

**根因**：不是卡片坏了，是 SPA 在后台标签里不渲染详情。

**处置**：**重新 navigate 一次搜索页**（强制整页加载）再 `open`，一次就成。
别急着重试同一张卡，更别直接判否。

### 15. 图发成功了，脚本可能报 `NOT_SENT`

**现象**：`img 0->0 NOT_SENT`，但会话列表预览已经显示 `[图片]`。

**根因**：后台标签重渲染后计数读到 0。

**处置**：`send_img2.py` 注入后会重新打开会话复查一次。
排查这类问题**看会话列表预览的 `[图片]` 比看计数器可靠**；别因为一次 NOT_SENT 就重发，
先开会话数一下。

### 16. 词表挖空不是死局，是换通道的信号

**现象**：`walk --next` 连续 10+ 张"已判否-跳过"。

**处置**：立刻切「宽词 + `jobType=1902` + 翻页」（第 3 步）。`1901` 是无效参数，别再用。

### 17. 每个搜索词结果集只有 ~15 张

**现象**：手动滚动到底也加载不出第 2 页（连滚 4 次卡片数恒为 15）。

**处置**：想拿更多卡只能 `&page=N` 翻页，别在"滚动加载"上耗时间。

### 18. 公司名留空会把简历发给无关的人

**现象**：补发图时 `open_conv` 用空串匹配，命中会话列表第一条。

**根因**：`indexOf('')` 恒为真。

**处置**：`deliver` 前硬校验公司名 ≥2 字、不是岗位名/HR 名、不是截断名；
投完立刻回读 `stream_progress.json` 最后一条，`company` 为空就停手记异常。

### 19. 公司名只出现在 `open` 之后

**现象**：`walk` 呈现的卡只有 `jobId/title/salary/city/industry`，没有公司名。

**处置**：公司名在右侧面板底部（`公司名 · HR头衔`）。`deliver` 的第二个参数填它。
别从别处猜。

### 20. `SKIP 标题不符` 先等 20 秒

**现象**：刚投完立刻补发，会话标题显示的还是 HR 名而不是公司名，匹配失败。

**根因**：会话列表渲染有延迟。

**处置**：等 20 秒重试一次（实测即成功）；再不行才用短名补。

### 21. `reply_check.py` / `stats.py` 裸跑报 `ModuleNotFoundError`

**现象**：`No module named 'scripts'`。

**根因**：这两个脚本按 `from scripts.xxx import` 组织的，需要技能根目录在 `sys.path`。

**处置**：带 `PYTHONPATH="$SKILL_DIR"` 运行。脚本内部已尽量自举，但 `--from` 等
回放路径仍建议显式带上。

### 22. 推荐页别再回去找新卡

**现象**：推荐页结构不兼容（卡片选择器只认出 1 张，`visible_total=1`），且推荐池
不会随天刷新到可用程度。

**处置**：新卡一律从 1902 通道拿。推荐页只在首轮 `recommend_exhausted=false` 时走一次。

### 23. CDP 端口起不来

**现象**：`cdp_client.py --launch` 执行了，但 12 秒内 `--check` 一直报端口没有 CDP 服务。

**根因**：三种。
1. **同一个 profile 已经有浏览器实例在跑** —— 新进程只会把命令行交给已有实例然后退出，
   调试端口根本没监听（最常见）。
2. 浏览器版本太旧，不支持 `--remote-debugging-port`。
3. 子进程没有脱离当前控制台，宿主会话结束时被一起回收。

**处置**：

- 用默认的独立 profile（`<工作目录>/browser-profile`），不要指向日常 profile；
  真要指向，先关掉所有浏览器窗口。
- 版本确认：`chrome://version` 里看内核，Chromium 100+ 都支持。
- `cdp_client.launch()` 在 Windows 上已经用 `DETACHED_PROCESS | CREATE_NEW_PROCESS_GROUP`，
  不要改回 `Start-Process`。
- 还是不行就把 `--launch` 打印出的那条完整命令手动粘到终端跑一次，成功后再 `--check`。

### 24. CDP 连上了但 `evaluate` 报错 / 拿到空值

**现象**：端口通了，`list_tabs` 也返回了标签，但第一个目标 `evaluate` 直接失败。

**根因**：连到了浏览器自己的内部页（`edge://sync-confirmation-dialog`、
`chrome://newtab` 这类），这些页面没有可执行的 DOM 上下文。

**处置**：`cdp_client.page_target()` 已默认跳过 `chrome://` / `edge://` / `devtools://` /
`about:blank`，优先挑真实网页。自己写脚本时也别硬用 `/json/list` 的第一条。

### 25. 浏览器"刚启动就查不到"

**现象**：`cdp_client.py --launch` 打印了"已启动"，但紧接着 `--check` 就说端口没有服务；
或者等了十几秒再查，端口已经没了。

**根因**：宿主（IDE / 智能体 / 沙箱）在命令结束时回收整棵进程树。`Popen` 出来的浏览器
是这条命令的子进程，命令一退出就被一起杀掉，调试端口随之消失。
`DETACHED_PROCESS` 只能脱离控制台，挡不住 job object 级别的整树回收。

**处置**：用 `--serve`，它会留一个常驻父进程：

```bash
# 放进后台任务，这一轮投递期间一直运行
python scripts/cdp_client.py --serve --url https://www.zhipin.com/web/geek/jobs
```

人自己在终端里跑时，终端不关就行，`--launch` 够用。
别指望 `schtasks` / 计划任务兜底——多数受限环境禁用它。

### 26. 别自动迁移别人的个人档案

**现象**：升级后第一次跑 `bootstrap.py`，工作目录里突然出现一份带姓名、学校、项目经历的
`user_profile.json`，而你没填过。

**根因**：早期实现会在检测到旧位置（上一代技能包、共用电脑上别人的安装）时**静默复制**档案。
省事，但共用电脑上会把别人的身份带进你的投递——简历和招呼语全错，且发出去撤不回。

**处置**：迁移必须显式：

```bash
python scripts/bootstrap.py --migrate     # 确认"那是我的"之后再执行
```

默认只在检测到旧档案时**打印路径提示**，不复制；`paths.profile()` 也不会去读
上一代安装留下的文件。宁可退化成空档案（`onboard.py` 会重新问一遍），也不要静默用错人。

## 一句话总结

1. 浏览器只有交给桌面 shell（explorer / open -a / xdg-open）拉起的能活。
2. `hidden=true` 别判"走空"，走 `&page=N`。
3. 分页会重排，`fresh=0` 连测两页。
4. 别指望把被遮挡的窗口调到前台。
5. 页面 fetch 本地图床会被拦，改 base64 注入。
6. 记基线，否则今日累计算不出来。
7. 判否必 `reject`，否则反复重判。
8. 弹窗只点「留在此页」。
9. 猎头/外包看公司名后缀 + 行业字段，别读完整个 JD 才发现。
10. 投递结构按证据强度定，不按供给多少定。
11. 一名多岗共用一个会话，只发一份。
12. `fresh=0` 分清"真挖空"和"没加载"。
13. 留一个权重 0 的「用不上」组。
14. 面板空 → 重新 navigate 再 open。
15. `NOT_SENT` 先看会话预览的 `[图片]`。
16. 连续 10+ 张已判否 = 换 1902 通道。
17. 一个词就 15 张，翻页才有更多。
18. 公司名空/截断一律不投。
19. 公司名在 open 后的右侧面板底部。
20. `SKIP 标题不符` 等 20 秒。
21. `PYTHONPATH` 必须带。
22. 推荐页不产新卡，去 1902。
23. CDP 端口起不来 → 多半是同一 profile 已有实例在跑，用独立 profile。
24. CDP 连上却 evaluate 失败 → 连到了浏览器内部页，跳过 `chrome://` / `edge://`（about:blank 可用）。
25. 浏览器刚启动就消失 → 进程树被宿主回收，用 `--serve` 常驻。
26. 个人档案不自动迁移 → `--migrate` 显式执行，否则共用电脑会串身份。
