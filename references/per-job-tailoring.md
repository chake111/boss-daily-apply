# 逐岗位定制简历（全国投放）

适用：用户要求「按 JD 改简历再投」，而不是「用一份通用简历批量投」。
代价是每一份都要单独出图、单独补发，因此节奏和默认流程不同。

## 一、全国搜索：城市码是 `100010000`

BOSS 的「全国」不是 `10001000`（少一个 0），后者会直接返回
「没有找到相关职位」，而且**不报错**——探供给只会显示 `fresh=0`，看起来像"这个词挖空了"。

确认办法：点搜索栏的「城市」→ 选「全国」，看地址栏的 `city=` 值。
写进 `user_profile.json` 的 `city_code`，`target_city` 写「全国」。

城市门禁对「全国」是通配：`_live_driver.mechanical_ok` 里
`city in ("全国", "不限", "任意")` 时跳过城市比对。否则每张卡都会因为
`city '武汉' != '全国'` 被机械否决，`walk` 直接 `view_exhausted`。

## 二、推荐页优先的硬规则与全国搜索的冲突

`walk <关键词>` 之前要求 `recommend_exhausted=true`。但推荐页是按账号的
「求职期望城市」出的（例如深圳），做全国投放时那一页全是外地要跳过的卡。

处理：先把推荐页滚到底让 `recommend_exhausted` 置真（它会因为城市不符被逐张跳过，
这是预期行为），之后关键词页就放行了。**不要**为了绕过这条规则去改 `walk_state`，
那个标志还有其他分支在读。

## 三、一个岗位的完整循环

```bash
# 1. 呈现下一张卡（自动跳过机械否决与已判否）
python scripts/_live_driver.py walk --next

# 2. 读 JD 全文（含末尾 HR 活跃度，别截断）
python scripts/_live_driver.py open <jobId>

# 3. 判：deliver / reject。投之前先出这一份的简历
python scripts/render_resume.py --config job.json --jobtitle <岗位名>

# 4. 投 + 当场补发这一份（图与岗位一一对应，不留到批次末尾）
python scripts/apply_one.py --jid <jobId> --company <公司> --salary <薪资> \
    --industry <行业> --direction 全栈开发 --jobtitle <岗位名> --img <上一步的 png>

# 5. 不投就显式 reject，别直接走开
python scripts/_live_driver.py reject <jobId>
```

投完一次 `deliver`，BOSS 会把页面带回搜索首页并重排列表。**必须重新导航回关键词页**
（带 `city` 和 `jobType=1902`）再 `walk --next`，否则会静默退回第 1 页并丢掉实习筛选。

## 四、附件名有 80 字节上限

BOSS 附件名的限制是 **UTF-8 字节数**，不是字符数：一个汉字 3 字节。
中文简历名很容易在"看起来才 40 多个字"的时候就已经超了。

`render_resume.py` 生成的格式：`姓名-岗位-学校-手机号.png`——**专业从一开始就不进文件名**。
以「冯键怀 / 全栈开发实习生 / 广西农业职业技术大学 / 13317698596」为例是 38 字符、
**78 字节**，刚好在限内，一个字段都不用丢。

真的超限时按 **学校 → 岗位 → 手机号** 的顺序丢，每次丢一个再重新量字节：

- 学校先丢：它通常最长（10 个汉字就是 30 字节），丢一个基本就回到限内；
- 岗位其次：只剩「姓名-学校-手机号」时仍能对应到人；
- 手机号最后：它在简历正文里也有，但 HR 直接回联靠它，用户也点名要保留。

专业不参与——打开简历第一屏就能看到，而且从学校名能推断出一部分，占字节最不划算。

## 五、和默认流程的差异

| | 默认（通用变体） | 逐岗位定制 |
|---|---|---|
| 简历图 | `resume/{variant}.png`，按方向固定 4 张 | 每投一家出一张，命名带岗位名 |
| 补发时机 | 每满 5 份批量跑一次 `send_followup` | 投完当场 `apply_one`，图与岗一一对应 |
| 补发寻址 | 可按公司名短名 | 一律 `--job <jobId>`（同名公司/同司多岗会串档） |
| 溢出风险 | 低（模板固定） | 高（每份内容长度不同），`render_resume.py` 溢出时退出码 3 |
| 供给消耗 | 一份图可复用 | 图不可复用，供给按"岗位"算而非按"方向"算 |

## 六、失败处置

- `render_resume.py` 退出码 3（OVERFLOW）：先删内容再重渲，**不要**把被裁掉的图发出去。
- `apply_one.py` 返回 `stage: deliver`：本次没投出去，不要补发图（会给无关岗位发简历）。
- `apply_one.py` 返回 `img: false` 或 `msg: false`：投递已成功，只是补发没成；
  用 `send_followup.py --job <jobId> --msg --img <同一张>` 重试，别换图。
- 图名与 `--jobtitle` 对不上时脚本会 `WARN`：多半是拿了上一家的图，停下来核对。
