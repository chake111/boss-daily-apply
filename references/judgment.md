# 判定标准

> 这是唯一权威的判定表。`SKILL.md` 和 `runbook.md` 里的判定都指向这里，改规则只改这个文件。
>
> 分工：`screen.py` 只处理**无歧义**的机械红线（外包/猎头/非技术岗标题/硬性届别）。
> 方向是否真的对口、JD 是不是"标题写开发正文全是装软件"，由**智能体读完 JD 后语义判断**。
> 不要把语义判断塞进黑名单——那会把"标题没有关键词但确实是好岗"的卡误杀。

## APPROVE（需同时满足）

- **城市**：目标城市。JD 写 "base 大亚湾/惠州/东莞" 的不算深圳（按 `user_profile.target_city` 判断）
- **性质**：实习 / 在校生 / 校招岗（实习生、日常实习、明年届校招都算）
- **技术栈**：Java / Spring Boot / Vue / 前端 / Python / AI 应用 / Agent，任一即可
- **学历**：本科及以下；经验不限或 1 年以内
- **届别**：明确接受你的毕业届别（写"仅限上一届"或"仅限下下届及以后"的不投）

## REJECT

### 岗位性质
- 非技术岗：销售、市场、地推、客服、运营、产品经理、行政、设计
- 非开发技术岗：测试/QA、硬件/PCB、实施顾问、ERP/财务系统运维、IT 支持
  （JD 主体是后端/前端/AI 应用开发才算；"标题写开发、正文全是测点/画板子/装软件"的按这条拒）
- 正式全职岗（还在校不能全职；除非明确写"可实习/实习转正"、或写明"应届生/在校生可投"）
- 兼职、按小时结算、按项目结算、长期远程外包
- 外包派遣、人力驻场、外派、猎头代招

### 硬门槛
- 要求 3 年以上经验；标题写实习但正文要 4-5 年经验的假实习
- 硬卡学历：要求硕士、要求 211/985（写"优先"的照投，写"必须/仅限"的跳过）
- 非技术硬门槛（如"要会粤语"）——其余条件再好也过不了
- 明显亏待：日薪低于 80 元、一周 6 天或大小周、一次绑定 12 个月

### HR 活跃度（刷掉最多的一类，别一刀切也别放宽）
- 可投：在线 / 刚刚活跃 / 今日活跃 / 3 日内 / 本周 / 本月 / 2 周内 / 3 月内 / 2月内
- 直接拒：4 月内 / 5 月内 / 半年前 / 年前
- 例外：岗位价值极高（大厂直招、技术栈完全对口、明确你的届别）**照样不发**，
  写进"值得破例"等人拍板。不要自作主张投出去。

### 其他
- 岗位描述明显和简历无关

## 边界案例（实测，照这张表判，别临场纠结）

| 看到的情况 | 判 | 理由 |
|---|---|---|
| 标题带"实习"，JD 写"1-3 年 / 1-5 年经验" | 拒 | 假实习 |
| 标题写"开发"，JD 主体是现场部署/等保整改/防火墙/DBA 迁移/CRM PaaS 配置 | 拒 | 实施/运维 |
| 公司后缀"猎头顾问/招聘顾问"，或行业字段是"人力资源服务" | 拒 | 猎头/派遣 |
| 知名外包：法本、科锐国际/科锐尔、外企德科、中软、软通、博彦 | 拒 | 外包 |
| "AI 应用实习生"但正文是视频制作/文案生成/内部培训带教 | 拒 | 内容运营，不是开发 |
| 数据标注、AI 训练师、AI 产品经理、算法研究（要论文/博士） | 拒 | 方向不符 |
| 学历写"研究生优先/优秀本科亦可" | 投 | "优先"不是硬卡 |
| 届别写"下下届及以后优先" | 投 | 是"优先" |
| 届别写"仅限下下届" | 拒 | 是"仅限" |
| K 薪（如 14-17K）但学历栏写"在校/应届"、正文写你的届别 | 投 | 校招岗，别被 K 薪吓退 |
| 薪资写"元/天"且 JD 写"每周 5 天、长期实习" | 投 | 实习计薪 |
| 要求"精通 C++"或图形学/渲染/CUDA/顶会论文 | 拒 | 技术栈不符 |
| "零基础可培养/包吃住/前期培训"，公司是管理咨询类 | 拒 | 培训招生陷阱 |
| HR 头衔是"教务主管"，JD 写"课程交付" | 拒 | 培训机构内招 |
| 标题带"青年领袖计划" | 拒 | 管培/招生套路 |
| 标题像技术岗，JD 全文是叠衣服/抓握动作采集 | 拒 | 机器人数据采集，标题骗人 |
| 全职 15K+ 且写"接受无经验+线上面试" | 拒 | 骗简历套路 |
| JD 写"毕业年份 2028 届"而你是 2027 届 | 拒 | 届别不符 |
| 学历栏标"硕士"但正文写"本科及以上在读" | 投 | 正文优先，接受可能被系统过滤 |
| 薪资写"元/时"或注明"项目制" | 拒 | 按小时/项目结算 |
| 大厂直招岗 | 查重 | 往轮已投过 2+ 个岗位的一律不投 |
| 公司名被截断（`某某市某某区某某…`） | 拒 | 过不了公司名硬校验；这类"一句话 JD + 中专可投"的小作坊岗质量可疑 |

## 同公司规则

- 同一岗位换 HR 重复发帖 → 只投一次（按"公司+岗位名"去重）
- 同一公司不同岗位 → 本轮最多 2 个，超了跳过
- 往轮已投过的公司 → 不再投；除非方向完全不同且特别对口，在汇报里单列等人拍板

## 公司名硬校验（投递前必过）

`deliver` 的第二个参数必须是**右侧面板底部**那行的公司名（`公司名 · HR头衔`）。
以下情况一律不许 deliver：

- 不足 2 个字
- 明显是岗位名或 HR 名
- 被截断（带 `…` 或明显缺字）

**为什么这么严**：补发简历图时 `open_conv` 用 `indexOf` 匹配会话标题，空串恒命中列表第一条，
会把简历发给完全无关的 HR，而且撤不回。投完立刻回读 `stream_progress.json` 最后一条，
`company` 为空就停手并记为异常。
